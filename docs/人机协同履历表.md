## 二、项目分工与 AI 参与环节、修改验证过程

### 分工

**本人（刘宇翔）负责**：创意与需求定义、多智能体架构决策（规划/执行分离、辩论回退机制、强条否决优先级）、结构专业知识把关、规范条文工程语义复核、每一次 AI 产出的验证合入决策、现场演示答辩。

**AI（编程智能体 WorkBuddy）负责**：系统架构设计辅助、代码实现、视觉设计、自动化测试、部署发布。

**AI（豆包 / DeepSeek）负责**：规范知识库材料整理、第三方评审建议。

### AI 参与环节

```
需求定义（人机共创）
  → 方案架构（AI 主导设计，人工确认"大模型不参与数值计算"底线）
  → 编码（AI 完成）
  → 验证（AI 自动化 9 套 312 项回归 + 人工抽检）
  → 视觉（AI 按"顶级美学"标准迭代 5 批）
  → 部署（AI 完成源码与线上双分支发布）
  → 答辩材料（AI 起草、人工修订）
```

### 修改验证过程

每一批改进都遵循 **"AI 改 → 全量回归（typecheck / eslint / 9 套 312 项断言）→ 线上核验 → 人工复核"** 的闭环：

- 涉及**结构计算**的修改，一律由本人按现行规范人工复算确认后才上线；
- 涉及**线上发布**的修改，均以实际访问线上产物核对关键功能为准（不以"推送成功"代替）；
- 历次修改均有 git 提交记录可追溯，累计 **95 次提交**；
- 通过 **9 套共 312 项**自动化回归测试（覆盖规范判定 / 领域调节 / 决策裁定 / 反事实推演 / DAG 调度 / 记忆系统 / 元认知 / 端到端管线 / 真实模式专项）。
